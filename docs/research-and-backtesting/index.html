    Trading hypothesis #

    A falsifiable statement that specified market information and trading rules are associated with a measurable outcome under stated timing, cost, and risk assumptions.
    Intuition: It turns an informal trading idea into a claim or design choice that can be evaluated against dated evidence.
    Mechanics: State the information set, decision rule, forecast horizon, instruments, benchmark, costs, and rejection criterion before evaluating dated data.
    Failure modes: Results can mislead when hindsight, multiple testing, nonstationarity, costs, or unavailable historical information are ignored.
    Misconceptions: A favorable historical result is evidence about the tested sample and assumptions, not proof of a durable profitable edge.
    Example: Hypothesis: stocks with positive 12-month momentum outperform the equal-weight universe over the next month after 20 basis points of round-trip costs.

    Signal #

    A dated numeric or categorical output that a trading process uses to express expected return, risk, or an intended action.
    Intuition: It turns an informal trading idea into a claim or design choice that can be evaluated against dated evidence.
    Mechanics: Compute it only from information available at the decision timestamp, then map its value to a forecast, rank, or order rule.
    Failure modes: Results can mislead when hindsight, multiple testing, nonstationarity, costs, or unavailable historical information are ignored.
    Misconceptions: A favorable historical result is evidence about the tested sample and assumptions, not proof of a durable profitable edge.
    Example: A five-day return of +4% produces a +1 momentum signal and a target long position at the next tradable price.

    Feature #

    An input variable supplied to a statistical or machine-learning model, derived from raw observations without using future information.
    Intuition: It controls what information the model receives and in what numerical representation.
    Mechanics: Define its timestamp and lookback, fit any transformation on training data, and construct the same value identically in validation and live use.
    Failure modes: Fitting the operation on the full dataset leaks future information; revisions, outliers, and missing values can also distort results.
    Misconceptions: A cleaner or rescaled dataset is not automatically more truthful; transformations must preserve timing and economic meaning.
    Example: At each close, 20-day realized volatility computed through that close is a feature for predicting next-day range.

    Label #

    The observed class or value assigned to an example as the outcome a supervised model is trained to predict.
    Intuition: It controls what information the model receives and in what numerical representation.
    Mechanics: Define the event window and labeling rule, align it after the feature timestamp, and prevent overlapping outcomes from leaking across splits.

    Misconceptions: A cleaner or rescaled dataset is not automatically more truthful; transformations must preserve timing and economic meaning.

    Training set #

    The observations used to estimate model parameters and fit data-dependent transformations.
    Intuition: It estimates how a fitted choice behaves on observations that were not used to fit that choice.
    Mechanics: Restrict fitting, feature selection, scaling, and imputation to these rows before applying the learned operations elsewhere.
    Failure modes: Random splitting, overlapping labels, repeated tuning, or an unprotected final test set can produce optimistic estimates.
    Misconceptions: Validation measures conditional generalization under a split design; it does not guarantee future market performance.
    Example: A 2015-2021 sample fits a scaler and classifier; no 2022 values enter either fit.

    Backtest #

    A historical simulation that applies explicit strategy rules to past data to estimate how the strategy would have behaved under stated assumptions.
    Intuition: It turns an informal trading idea into a claim or design choice that can be evaluated against dated evidence.
    Mechanics: Advance through dated observations, form decisions from the contemporaneous information set, simulate orders and costs, and update cash and positions.
    Failure modes: Results can mislead when hindsight, multiple testing, nonstationarity, costs, or unavailable historical information are ignored.
    Misconceptions: A favorable historical result is evidence about the tested sample and assumptions, not proof of a durable profitable edge.
    Example: A monthly momentum rule is replayed from 2010 through 2020 with delisted stocks, next-open fills, fees, and slippage.

    Event-driven backtest #

    A backtest in which a clock processes market, signal, order, fill, and portfolio events in timestamp order.
    Intuition: It is part of the machinery that converts strategy instructions into simulated positions, cash flows, and performance.
    Mechanics: Each event updates state and may enqueue later events, preventing strategy logic from reading beyond the current time frontier.
    Failure modes: Simplified timing, liquidity, fee, borrow, funding, or corporate-action assumptions can make simulated results unattainable live.
    Misconceptions: A detailed simulator reduces modeling error but cannot reproduce every queue event or future market condition.
    Example: A 09:30 quote triggers an order event; a later trade event partially fills it and then updates cash.

    Walk-forward analysis #

    Sequential evaluation that repeatedly fits or selects a model on past data and tests the frozen result on the next unseen time block.
    Intuition: It estimates how a fitted choice behaves on observations that were not used to fit that choice.
    Mechanics: Move the training and test boundaries forward, refit only on data preceding each test block, and concatenate the non-overlapping test results.
    Failure modes: Random splitting, overlapping labels, repeated tuning, or an unprotected final test set can produce optimistic estimates.
    Misconceptions: Validation measures conditional generalization under a split design; it does not guarantee future market performance.
    Example: Fit on 2018-2020 and test 2021, then fit on 2019-2021 and test 2022.

    Rolling-window analysis #

    Walk-forward analysis whose training window has fixed length and drops the oldest observations as it advances.
    Intuition: It estimates how a fitted choice behaves on observations that were not used to fit that choice.
    Mechanics: Choose train and test lengths, fit on each trailing window, and evaluate on the immediately following block.
    Failure modes: Random splitting, overlapping labels, repeated tuning, or an unprotected final test set can produce optimistic estimates.
    Misconceptions: Validation measures conditional generalization under a split design; it does not guarantee future market performance.
    Example: Use the prior 36 months to fit each model and predict the next month, then roll both boundaries forward one month.

    Expanding-window analysis #

    Misconceptions: Validation measures conditional generalization under a split design; it does not guarantee future market performance.
